# Changelog

All notable changes to crankpath. All dates are 2026. Nothing has been released, pushed or published yet. Licence: Apache-2.0 (the owner's decision, 2026-11-15): [LICENSE](LICENSE) and [NOTICE](NOTICE).

The JSON output's `schemaVersion` is the stable contract: a breaking change to it, to `crankpath.yaml` or to the Action's inputs and outputs is listed here (C7, C2, C10), and a breaking JSON change raises `schemaVersion`.

## 0.1.0: unreleased

The release day replaces `unreleased` in this heading when the owner publishes ([release checklist](docs/release-checklist.md)). Built and packed locally only; the npm package, the public repository and the Action's first hosted run all wait for the owner's go.

### What v0.1 does

- **Reads a GitOps repository, never a cluster.** Argo CD Applications (single and multi-source) and ApplicationSets (list, git, matrix and merge generators, and cluster generators through a declared `clusters:` block), Flux Kustomizations, HelmReleases and their sources, Kustomize roots and plain directories. A positional `https` URL is fetched read-only at a full commit (`--rev`), and `repos: {fetch: true}` entries at their default branch ([fetching](docs/fetching.md)).
- **Renders Helm and Kustomize** with the helm and kustomize found on `PATH`, behind a closed allowlist of commands and options, with no shell, an environment built from nothing, a private directory, a time limit and output caps; every chart is rendered twice and the differences it sees are flagged. The tested pair is helm v4.3.2 with kustomize v5.8.1.
- **Builds the dependency graph** from the fields it reads: sources, Secret and ConfigMap references, Service selectors, repository credentials, External Secrets stores, cert-manager issuers, the Vault seal, cloud identities, Flux `dependsOn`, and hosts in the fields that name a host. Every edge is `extracted` or `declared`.
- **Reports** every dependency cycle (strongly connected components, with the shortest cycle shown and `--explain` for the evidence), the nodes not startable from a cold start with the nearest reason, the external preconditions, and an ordered restoration plan with the manual crank steps marked, under a disclaimer that it is an order, not a schedule.
- **Says what it could not see.** Every opaque, skipped, unreadable, limited or timed-out source is named and counted with one of a closed set of reasons; the opacity line is a floor (`at least`) when anything was unreadable; a run with any gap is `ANALYSED WITH GAPS`, and every report closes with what it does not model ([what it cannot see](docs/what-it-cannot-see.md)).
- **Takes declared facts** in `crankpath.yaml` ([reference](docs/crankpath-yaml.md)): externals and their cold-start availability, cranks (`creates`, including `render:<path>` for a directory applied by hand, and `reroutes`), repository identities, host matches, declared edges and `clusters:`. Each is labelled `declared (unverified)` or `documented, not verified`, never as verified.
- **Outputs** `text` (80 columns, ASCII in its own words), `json` (schema version 1, [JSON output](docs/json-output.md), `schemas/` in the repository) and `mermaid` (a Markdown document with a text fallback); byte-identical for the same inputs and tool versions, except where a chart's own rendering varies.
- **A GitHub Action** (`action/`, [the Action guide](docs/action.md)) that compares a pull request's head with its merge base: it fails on a new uncranked cycle (`FAILED`), says NOT CHECKED (which also fails the job) when it cannot compare or when the head has a gap or relies on a declared fact the base did not, and lists the declared facts the pull request adds. `NO_NEW_CYCLES_FOUND` is never worded as a pass. It has never run on a GitHub-hosted runner.
- **The release round** (2026-11-16): `SECURITY.md` with GitHub private vulnerability reporting as the contact, `CONTRIBUTING.md` with the lanes and the rules for changes, this changelog, `.github/workflows/release.yml` (publishes with provenance only from a pushed `v<major>.<minor>.<patch>` tag, after the offline gate; actions pinned by full commit SHA; held by `test/u12-docs-release/release-workflow.test.ts`), [the release checklist](docs/release-checklist.md), and the README rewritten with the opacity statement first.

### Limits at this version

- **Most of a real estate is opaque to a static read.** On the five census estates, run as published, the opaque share is over the one-third threshold of D12 by both of crankpath's counts (the figures are in the README and the [census record](docs/census.md), section 5). The largest walls are Flux Kustomizations whose source is not a `GitRepository`, GitRepositories only the bootstrap creates, and Helm inflation inside kustomize. Read every result as what the repository shows.
- **Platforms.** Meant for macOS and Linux (arm64 and x64) by design (D2); this build was run on macOS arm64 only (Node 22.23.2), and Linux and x64 have not been run. Windows is not supported.
- **The Action has never run on a GitHub-hosted runner**: its build step, `setup-node`, the runner's own `GITHUB_*` values and the summary's rendering on github.com are unexercised until the owner's first push.
- **Determinism has a stated exception.** khuedoan/homelab at 8b9d40f holds charts whose rendering varies between runs, so its full JSON differs from run to run by one floating note ([limits](docs/limits.md)); two renders that agree cannot prove a chart never varies.
- **Not observed against real servers**: real helm's wording for 401, 403, 404 and rate limits (the classifier falls back to a generic message), a redirecting server, and DNS rebinding to a private address (the guard sees names, not addresses). helm follows redirects itself when it pulls a chart.
- **Not rendered by Mermaid itself** in the tests: the Mermaid output is checked by a structural test of the grammar crankpath writes.
- **A run killed with SIGKILL** leaves its private directory under the cache's `tmp/`; the next run with the same cache removes it.
- **Measured on one machine.** Every timing and memory figure in [limits](docs/limits.md) is that machine's, not a promise (OD-7).
- **What static analysis cannot see** (runtime-only dependencies, cluster-created state, controller start-up, timing and cold-load pickup, whether a crank works): [what it cannot see](docs/what-it-cannot-see.md).

### Decisions taken for the owner

The owner was away for the build; the build lead took these, following the design's recommendation where it has one. Each can be reversed.

- **Licence** Apache-2.0, not private (the owner, 2026-11-15). **Security contact**: GitHub private vulnerability reporting (2026-11-16).
- **Census estates (OD-26)**: gitops-bridge-dev/gitops-bridge, mortennordbye/homelab, acelinkio/argocd-homelab, ricsanfre/pi-cluster and niki-on-github/nixos-k3s, chosen by a rule written before any count ([census record](docs/census.md)). Two figures are kept: the static estimate made before the discovery code existed, and the real-discovery count, the headline.
- **The v1.1 item for the top opacity reason (D12)**: the static estimate pointed at cluster-created Secrets; real discovery points at Flux sources other than `GitRepository`, Helm inflation in kustomize and bootstrap-created GitRepositories. The owner picks.
- **Tested pair** helm v4.3.2 with kustomize v5.8.1 (OD-13 named v4.3.1; Homebrew offered v4.3.2 on 2026-11-15).
- **GPL and MPL sources**: the homelab goldens hold commits, node ids and counts only; the Vault fixture is hand-written in the shape of hashicorp/vault-helm, and its goldens hold crankpath's report of it, not the chart's templates or rendered output.
- **The deny-list (OD-28)** is read only from `CRANKPATH_DENYLIST_FILE`; unset, the release check fails with NOT RUN, and the owner supplies the file.
- **`repos: {fetch: true}`** is kept (OD-10), and honoured from the scanned repository's own `crankpath.yaml`; such an entry is always fetched without a token. The owner may want fetch entries honoured only from `--config`.
- **Declared facts and the run status**: a declared fact that changes the extracted graph (a `match:` override, a declared edge, a `repos:` mapping, a `clusters:` block) is a gap; externals declared available, `served_by` and cranks are plan assumptions, always listed, not gaps by themselves (BR1.10).
- **The Action**: NOT CHECKED fails the job (OD-11); the head's `crankpath.yaml` is evaluated and every fact it adds is listed as unverified (OD-27 b); with no new cycle, any gap item of the head that the base does not have, compared item by item, or a declared fact the base did not rely on, makes the result NOT CHECKED, so a gap that only moves reads as NOT CHECKED too (a false NOT CHECKED, never a hidden cycle).
- **Precedence of reasons**: a blocker outranks a gap (a node behind a cycle and an opaque node is `blocked`), and an extractor failure makes every node unverified.
- **Host placement**: a host that could be in-cluster is an unresolved item, never an external; an unmatched host that cannot be in-cluster (a two-label host only under a delegated top-level domain of the dated IANA list) is an external with unspecified cold start ([host placement](docs/host-placement.md)).
- **Kubernetes names**: an RBAC object named `system:...` is skipped and named as an invalid name; `optional: true` references make no edge; a ClusterIssuer's references resolve in `cert-manager`, cert-manager's default; the cluster-provided list is as recorded and may be widened.
- **Fetch and render environment**: no proxy variable reaches helm or git; a cache inside the scanned tree is not trusted; scheme-less OCI chart sources and absent `optional` Flux values are opaque; Kustomize roots and chart directories nothing deploys are listed, not graphed, unless a crank says they are applied by hand; `render:.` is allowed and listed, so the Action shows a pull request that adds it.
- **Fetch form**: an abbreviated `--rev` is refused (a server serves full object names only); the token goes as Basic authentication with user `x-access-token`, so a forge that wants a Bearer token is not served.
- **Golden lane**: a helm or kustomize version other than the reviewed one makes a case SKIPPED, never FAIL or a pass; `--observe` and `--pin` exit 2.
- **The package** ships `dist/`, `README.md`, `CHANGELOG.md`, `LICENSE`, `NOTICE` and `package.json` only: `schemas/` is not packed (the schema is in the repository and documented in [JSON output](docs/json-output.md)), and no `npm-shrinkwrap.json` is added. The release workflow installs npm 11.21.2 for trusted publishing (the highest 11.x on 2026-11-16, [lookups](docs/lookups.md)).
- **Corpus**: four trimmed, unmodified copies under Apache-2.0 or MIT (fluxcd/flux2-kustomize-helm-example, gitops-bridge-dev's control-plane template, acelinkio/argocd-homelab, bjw-s-labs/home-ops); the documentation example is crankpath's own fixture, `test/fixtures/docs-example/`.

### Amendments to the written design (each awaits the owner)

The design is kept outside the repository; its decisions are in plain words in [docs/design](docs/design/decisions.md). These changes to it were made during the build, each recorded in [BUILD-NOTES](BUILD-NOTES.md) under the bolt named. The design text itself is not edited.

| # | What changed | Replaces | Why, and where recorded |
|---|---|---|---|
| 1 | Apache-2.0, not private, with `LICENSE` and `NOTICE`; check-pack checks Apache-2.0 | D1's `"private": true`, AC12.3.1 and BR12.4 (`private`, `UNLICENSED`, no LICENSE) | The owner's licence decision of 2026-11-15 (B0, B9). |
| 2 | The Mermaid cap is Mermaid's own two limits (`maxEdges` 500, `maxTextSize` 50,000, Mermaid 12.3.0), not a node count; whole cycle components are drawn while they fit | OD-18 (a node cap) | A node count cannot make the text fit when labels vary in length (B0, B6). |
| 3 | YAML depth limit 287, measured below the parser's stack with half of it kept for callers, and an early lexeme count per file (`lexemesPerFile`) | the depth "derived from what the parser and a manifest need"; no lexeme limit | The yaml package's stack binds at varying depths, and a 10 MB flow sequence ran the heap out of memory before any other limit applied (B0 and its reviews). Files of 288 levels and more, valid to Kubernetes, are refused by name. |
| 4 | The census label is `static-estimate`, and real discovery counts an unexpandable ApplicationSet or an unreadable Flux Kustomization once | C11 (`static-upper-bound`), OD-19 (once per generator) | No static reading can bound what only a fetch or a render shows; crankpath's report has no per-generator count of an opaque ApplicationSet. | 5 | Sync waves are a node attribute, not `orderingOnly` edges | the `orderingOnly` edges of the sync-wave rule | One edge per pair of objects in consecutive waves is quadratic on a hostile job; BR5.3 holds, a wave never makes an edge (B1). |
| 6 | A crank's `creates` removes all of the node's outgoing edges, and `render:<path>` names a directory and everything under it | BR7.7 (`deployed-by` only; a path that "equals") | FR7.4 says the crank satisfies the node's own dependencies; plain objects carry file paths, and the research's `render:system/argocd` names a directory (B5). |
| 7 | A `render:<path>` crank renders a chart or Kustomize directory applied by hand as a new source, with two optional crank keys, `namespace:` and `release:` | C2 (no such keys); FR7.4 without a render | khuedoan/homelab's bootstrap renders `system/argocd` by hand as release `argocd` in namespace `argocd`; without the crank that estate is `NOTHING ANALYSED` (B7, lead decision of 2026-11-16). |
| 8 | Blockers name the nearest root cause, one per node, with `via`; an unspecified external is itself `blocked` (`external-unspecified`) | listing every root cause; an unspecified external as unverified | Every root cause is quadratic on hostile graphs; an external whose cold start nobody declared cannot be taken as startable (B5). |

| 11 | Credentials match only when the transport agrees (ssh with ssh, https with https), exact `repository` before the longest `repo-creds`, a tie `credential-ambiguous` | credential matching by normal form only | Argo CD does not offer an ssh key to an https URL; the tie follows the ambiguity rule of OD-14 (B4). |
| 12 | Query parameters with credential-like names are redacted from printed URLs, as userinfo is | BR1.11 (userinfo only) | A token can ride in a query string (B0 third review). |
| 13 | `--format mermaid` writes a Markdown document: a text header, the `mermaid` fence and a text fallback | bare Mermaid (FR8.3) | The run status, the gaps and the fallback must reach the reader (NFR14) (B6). |
| 14 | A `--no-color` flag besides `NO_COLOR` | C6 (`NO_COLOR` only) | A per-run switch; colour never says what a word does not (B6). |
| 15 | The JSON schema is strict (`additionalProperties: false`, every field required); consumers are still told to ignore unknown fields | an open schema | A field added without a schema update fails the tests (B6). |
| 16 | The runner checks a closed option list per command, fixes the locale to `C` and passes no proxy variable; `--verbose` prints counts, never a command line | the (tool, subcommand) pair; an inherited locale; NFR15.1's "redacted command line" | Cluster flags are refused by construction; output is byte-identical across locales; arguments hold repository text and private paths (B2). |
| 17 | A floating chart range is always re-resolved, and under `--no-network` it is `offline` | resolving ranges from the cache | crankpath does not resolve ranges against its cache (B2). |
| 18 | A matrix or merge generator with no `clusters` child is expanded without a `clusters:` block; a cluster's server URL or project other than `in-cluster` is `cluster-inputs-missing` | BR3.13 (the block for every matrix and merge) | Only a `clusters` generator needs cluster inputs; the block gives labels and annotations, not a server URL (B3). |
| 19 | A failed positional fetch exits 1, not 2 | exit 2 for nothing analysed | "Nothing analysed" would read as an empty repository; nothing was read (B3). |
| 20 | The Action's `new-cycles` output is empty when the result is NOT_CHECKED | C10 (an integer) | With no comparison no count exists, and `0` would read as none found (B8). |
| 21 | The Action copies both commits raw from git (`ls-tree`, `cat-file --batch`), the base being the merge base | a `git worktree` or `git archive` | A worktree runs hooks; `git archive` and `checkout-index` apply attributes and filter drivers that could hide a base `crankpath.yaml` (B8 and its reviews). |
| 22 | With no new cycle, any gap item of the head absent from the base, or a declared fact the base did not rely on, makes the Action NOT CHECKED | gaps stated beside the result (BR10.7, BR10.8) | A pull request could hide a cycle by making what carries it unreadable (invalid YAML, a symbolic link, an opaque source); removing one gap never makes up for a new one (B8 reviews, owner decisions taken by the lead). |
| 23 | The Action's words "pass" and "green" appear only negated (`Not a pass:`, `This job is not green.`) | never using those words | M7's own wording is kept; a test checks every use is negated and that passed, OK, clean and safe never appear (B8). |
| 24 | The claim map covers every output claim of every user document, not only the README's; records (the design copies, the research, the lookups, the census) are exempt from the content rules | BR12.3 (README claims) | A quoted output anywhere in the docs is held to a test (B9). |
| 25 | The corpus copies live under `test/corpus/<copy>/repo/` with the upstream `LICENSE` beside it, unmodified, trimmed by leaving files out | C11 (`LICENSE.<upstream>`) | crankpath scans `repo/` and never reads the manifest or the expectation as part of the estate; no file needs a "Modified" line (B9). |
