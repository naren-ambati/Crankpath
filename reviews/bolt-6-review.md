## 2. B1 text leak: siblings in other sections?

The leak: the evidence field printed bare when it matched a plain-character pattern. Checked for siblings in three ways:
1. Read every `${...}` interpolation in `text-renderer.ts` and `explain-renderer.ts`: repo-derived values are all quoted (`quote`, `quoteUrl`, `nodeRef`, `crankRef`); the unquoted ones are enums, counts, `s.item` (a number), `document` (a number) and fixed lists (`lostEdges`, `detail`, `reasonWord`; produced from constants in the planner and reader).
2. A leaf scan: for each string leaf of three Reports (Vault, Vault with a crank, self-managed fixture; about 1,100 leaves) the leaf was replaced by a marker and the text, explain and Mermaid outputs checked for the marker outside double quotes. Every hit was an enum or fixed word (`edges[].kind`, `cycles[].id`, `cycles[].label`, `runStatus.state`, `toolchain.crankpath`, `notModelled[]`, `plan.disclaimer`, `notStartable[].blocker`/`cycleLabel`, `unresolved[].why`, `controllerMatches[].controller`/`tool`). No repo-text leaf prints bare.
3. The hostile property test fills opaque, skipped, unreadable, unresolved, match, mapping, hidden-cycle, crank and plan-step slots (40 seeds); it does not fill `externals[].name`, `lostEdges`, `detail`, `origin.document`; those are covered by (1) and (2).
No sibling leak found.

## 5. Checked and found sound

- Mermaid injection, validated with the real parser: `mermaid@12.3.0` (`mermaid.parse`, jsdom shim, `review-b6/repros/parse.mjs`) parsed 301 of 301 documents (300 seeded hostile Reports with quotes, `"]; click n1 call alert(1)`, `%%{init}%%`, `<script>`, `<img onerror>`, backticks, fences, `#quot;`, `#35;`, `|`, `}{][)(`, CR/LF, U+2028, U+0085, bidi, lone surrogates, tag characters, plus the Vault document); a negative control (`n1["a"] --> --> n2`) fails the parser. Real CLI run with a hostile Deployment (`review-b6/repros/est`, `est2`) emitted no `click`, `href`, `callback`, `%%`, extra `subgraph`, `classDef` or `style` line from repo text; the only `subgraph` line is the legend. Rendering to SVG under jsdom failed on missing browser APIs, so HTML-label rendering of entity codes is NOT verified (the entity codes are decimal for ASCII specials only, and `#` itself is escaped, so `#35;` in the repo reads back as `#35;`).
- Markdown wrapper: both text blocks and the diagram are fenced; no line of the document starts with repo text (the strict `fences()` check throws on any line that could close a fence); repo ``` appears only inside a quoted value mid-line.
- Own words in Mermaid come from a closed alphabet (`own()` throws on anything else; `reason`, `flags`, kind, cycle id are enums or hashes).
- Text layout: no break before a quote, none after a colon label, none inside a quoted value; mutation kills it. Colour: only crankpath's own words, never inside a quoted value, never green, never for `--out`, JSON, Mermaid or a non-TTY; `NO_COLOR` empty is treated as unset (as no-color.org says); stripping gives the plain bytes.
- Elementary cycles: iterative Johnson; compared against a brute-force oracle on 3,000 random graphs (up to 7 nodes): identical sets, and `stopped` exact at the bound (`review-b6/repros/ec.mjs`). Timing: 100,000-node ring 318 ms; 400-node complete graph, 50,000-node hub and a 3,000-node back-fan stop at 21 cycles in under 70 ms. No stack growth.
- Signatures: sorted by id, frozen, `apps/v1`, in-cluster destination only, owner from the render job; no path into the graph (JSON has no `controllerMatches`).
- Mermaid over the cap: whole components in id order, and says so, with counts (a 20,000-node ring draws 0 of 1 components and says it).
