## 4. What I checked and found sound

- Reading from an arbitrary cache location: the copy takes only names matching loose/pack patterns, opens with `O_NOFOLLOW`, accepts regular files only, counts bytes before reading, writes `O_EXCL` into a directory crankpath made; verification runs on the copy, so a file swapped after the copy is irrelevant.
- crankpath writes the git directory's `config`, `HEAD`, `shallow` itself; refs, `packed-refs`, `info/`, alternates, hooks are never copied. `safe.bareRepository=explicit` with an absolute `--git-dir`.
- The allowlist: each new form has no options and no positionals, requires an absolute `--git-dir` (and `--work-tree` only for `checkout-index`), and the token header is refused for every form but `clone`.
- Fresh and cached reads go through the same `materialise`; an untrusted (in-tree) cache is never read and nothing it holds is kept.
- Mutation re-run of the pass-2 list (`mut.py`): the only survivors are the two copy-bound mutants (mut.py m08, m09, now masked by the checkout bound).
