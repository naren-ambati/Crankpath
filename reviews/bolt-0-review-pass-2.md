## 3. Where the fixes meet (answers to the brief's questions)

- **Census classifier, figures and labels.** Label `static-estimate`, `notSeen` (three items), `atLeast` and `againstOneThird` agree with each other for every committed estate: floors are `at least`, `not established` wherever the hidden part could change the answer, and `over one third` without qualification only for nixos-k3s (110 of 122, nothing uncounted, exact for what it counts). Nothing is counted twice: each Application, HelmRelease or list element is one source, a generator counted once is one unit, an object inside a `List` is expanded and the list object is not counted, and the chart-template files appear both in `unreadableFiles` and in `chartTemplateFilesUnreadable` by design (documented). Residuals: latent `at most one third` (m1), patches to non-source kinds (m2), cycle (m3), mixed units in the headline (m9).
- **`tokensPerDocument` arithmetic and sourcing.** `(2,500,000,000 - 103 MiB) / 664 = 3,602,404` reproduces. The runner size and the V8 formula are looked up and dated in `docs/lookups.md`. No realistic manifest is refused: a 3 MiB object (the API server's body ceiling) costs at most about 1 token per byte, 3.1 million, under 3.6 million; the largest real file in the five estates has 85,272 bytes. The value is derived from a heap, not from the API server's size, so that margin is luck, not derivation; say so. Cost and memory at the limit: M3.
- **`nestingDepth` 287.** No legitimate Kubernetes object is refused (the deepest real file has 14 levels; Kubernetes' own decoder allows 10,000, disclosed). The half-stack reserve is disclosed as a choice in `docs/limits.md` ("a stated reserve"), in the `basis` string and in the build notes (deviation 3, "a design choice"); it is not checked against any real call depth (B9). Disclosure is adequate; the header wording is n2.
- **`changed` outcome.** Growth is refused; shrinkage is not (m7); the wording is the regular-file word (m7).
- **SafeText.** Redaction hole M1; character set and `$` fixed and tested; side effects m11.
- **check-tree.** New rules do not flag any file in the tree (41 files, 0 findings, also from a clean clone). False-positive risk: short login names (m6). Slips: m4, m5.
