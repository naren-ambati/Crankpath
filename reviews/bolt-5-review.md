## 5. Checked and found sound

- Cranks cannot name paths outside the root: `..`, absolute and NUL paths are refused by ConfigReader and fail the run; `render:` is compared as a string against node origins, so symlinks are never followed (the walk already refuses them); `render:.` is allowed and prints as one documented step, never as verified.
- A reroute to an undeclared or unspecified external yields `blocked`, never startable; a reroute to a declared-available external is shown "declared, not verified" in text and in `plan.assumes.externals` (JSON).
- A reroute only removes `reads-source` edges to in-estate nodes; a crank that shrinks a cycle leaves it uncranked with its residual named; cycles a reroute closes are reported.
- A crank-created stub is not `not-defined`, and a crank cannot create an external.
- A repo object that defines a cluster-provided id becomes an ordinary node, so it cannot gain `startable` through the exemption list. The list is dated 2026-11-15 with per-entry lookups in `docs/lookups.md` and is small.
- `startable` is only built through the StatusModel constructor; the plan has a guard that a start step never holds a non-startable node, and the plan builds waves and `dependsOn` as constraints, drops contradicted ones and lists them, and lists blocked and unverified nodes unordered with reasons. The wave barrier encoding is linear.
- Determinism: sorted collections, id derivation, ties by code point; reversed-input test in the bolt; my runs matched.
- 100,000-node chain, ring (cranked and not), dense graph and many SCCs: no recursion, no stack growth; my 200,000-edge dense component with and without cranks ran in about 1.3 s each.
- Hostile `by`, `ref` and match text is quoted after fixed labels with visible control codes (thin slice with escapes: no line starts with repo text).
- Hard rules: no design-tool paths or names, no personal paths or hostnames in added lines; commit identity correct; Apache-2.0 and NOTICE untouched; no network in tests.
